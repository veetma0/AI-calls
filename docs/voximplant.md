# Исходящий звонок: Voximplant + ElevenLabs

Эта инструкция подключает самостоятельный AI Calls. В нём нет CRM, Telegram, перевода на менеджера или записи аудио. Сначала используйте режим `mock`: он проверяет интерфейс и очередь без провайдеров и расходов. Синтаксические и локальные тесты сценария не подтверждают работу реальной телефонной линии.

## 1. Что подготовить

- Аккаунты Voximplant Platform и ElevenLabs с доступной в вашей стране услугой. Условия регистрации, идентификации, страны номера и исходящих направлений определяет провайдер; наличие приложения не заменяет эти проверки.
- Собственный подтверждённый Caller ID и разрешённый тестовый номер получателя. Не используйте номера или агентов из чужих примеров.
- Доступный из Voximplant HTTPS-адрес вашего сервера, без пароля в URL.
- Одинаковый длинный случайный внутренний секрет на сервере и в Secrets Voximplant.
- Контакт с настоящим согласием на этот звонок. Для первого теста — ваш собственный номер в разрешённом списке приложения.

## 2. Агент ElevenLabs

1. Создайте агента, выберите русский язык, голос и модель, поддерживающую вызов инструментов.
2. Вставьте первую реплику и системный промпт из [`agent-prompt.md`](../voximplant/agent-prompt.md).
3. Объявите четыре динамические переменные из промпта. Сценарий передаёт их отдельно для каждого звонка; ключи в них не передаются.
4. В Tools создайте три инструмента типа **Client** с точными именами и параметрами из [`tools.json`](../voximplant/tools.json): `opt_out`, `save_outcome`, `end_call`. Включите **Wait for response**. Это описание объектов инструментов; при ручной настройке переносите поля, а не весь массив в поле промпта. Не добавляйте одноимённый системный `end_call` — его обработчик другой.
5. Сохраните/опубликуйте агента, скопируйте его `agent_id` в настройки сервера. При использовании версий убедитесь, что опубликована нужная конфигурация: этот сценарий не фиксирует отдельную ветку.
6. Проверьте диалог в консоли. Из консоли реальные client tools приложения не исполняются, поэтому проверку сохранения opt-out выполняют на собственном тестовом звонке.
7. Отключите хранение аудио в настройках ElevenLabs, если оно включено, и задайте срок хранения текстовых данных. Отсутствие `call.record()` в коде не меняет настройки хранения у ElevenLabs.

Официально: [динамические переменные](https://elevenlabs.io/docs/eleven-agents/customization/personalization/dynamic-variables), [client tools и ожидание ответа](https://elevenlabs.io/docs/eleven-agents/customization/tools/client-tools).

## 3. Приложение Voximplant

1. Создайте Application в Voximplant Platform.
2. В его **Secrets** добавьте:

   | Имя | Значение |
   |---|---|
   | `ELEVENLABS_API_KEY` | Ключ вашего ElevenLabs |
   | `AI_CALLS_BASE_URL` | Публичный адрес сервера, например `https://calls.example.com`, без завершающего `/` |
   | `AI_CALLS_INTERNAL_SECRET` | То же значение, что `INTERNAL_SECRET` на сервере |

3. В **Scenarios** создайте сценарий, вставьте целиком [`outbound.js`](../voximplant/outbound.js), сохраните/опубликуйте.
4. В **Routing** создайте отдельное правило и привяжите только этот сценарий. Его ID сохраните в настройках сервера как `VOXIMPLANT_RULE_ID`.
5. Разрешите исходящие звонки и подтвердите свой Caller ID в аккаунте Voximplant. Проверьте баланс, направление и тариф.
6. Management API credentials оставьте только на сервере. Браузер и ElevenLabs их не получают.

Не запускайте правило с произвольным номером в Custom data. Приложение передаёт только `job_id` и одноразовый `dispatch_token`. Сценарий получает номер и условия звонка после серверного подтверждения claim. Ручной повтор одного запуска не создаёт второй звонок: повторный claim отклоняется.

Официально: [исходящий ElevenLabs-сценарий](https://docs.voximplant.ai/voice-ai-orchestration/elevenlabs/outbound), [native ElevenLabs API](https://docs.voximplant.ai/api-reference/voxengine/elevenlabs/overview), [HTTP API Net](https://docs.voximplant.ai/api-reference/voxengine/net), [типы VoxEngine](https://cdn.voximplant.com/voxengine_typings/voxengine.d.ts).

## 4. Что происходит во время звонка

1. Сервер резервирует задание и запускает правило Voximplant один раз. При неопределённом ответе старт не повторяется автоматически.
2. Сценарий делает одноразовый `claim`, затем проверяет остановку. Ошибка, тайм-аут, неверный ответ или повторный claim означают: **не набирать номер**.
3. `callPSTN` вызывается один раз. По ответу абонента создаётся ElevenLabs client; динамические переменные отправляются до соединения медиапотока. Ожидание агента ограничено 15 секундами.
4. Звук идёт напрямую через нативный клиент Voximplant. При перебивании буфер речи агента очищается.
5. Звонок ограничен таймерами ожидания ответа и разговора. Каждые 5 секунд после предыдущей проверки опрашивается остановка. При двух подряд сбоях контроля звонок завершается. Из-за HTTP-задержек остановка не гарантирована ровно за 5 секунд; при здоровой сети это примерно один цикл.
6. `save_outcome` подтверждается только после сохранения. `opt_out` сначала записывает запрет звонков в базу и отменяет будущие задания, затем возвращает успех агенту. Дополнительно распознаются несколько буквальных фраз отказа от звонков в русском и английском транскрипте; это дополнительная защита, а не полное понимание всех формулировок.
7. Финальное событие использует постоянный ID. При временной ошибке отправки выполняются максимум три попытки с тем же ID. Телефонная линия закрывается сразу, сценарий ждёт подтверждения сервером перед `terminate`. Если подтверждения нет, сервер позже пометит задание неопределённым для ручной сверки; повторного звонка нет.

`completed` означает окончание соединённого разговора, а не продажу. `outcome` отдельно отражает сообщённый агентом результат; по умолчанию `unknown`. Для занятости, отсутствия ответа, ошибки и отмены есть отдельные статусы. Просьба о перезвоне не запускает второй звонок автоматически.

Транскрипт состоит из доступных событий ElevenLabs и ограничен 100 репликами, 1000 символами на реплику, 30 000 символами суммарно. Исправленные после перебивания ответы заменяются. Возможны отсутствующие события; это не сертифицированная дословная стенограмма. `conversation_id` сохраняется только если получено настоящее metadata-событие; идентификатор не выдумывается.

## 5. Приёмка на собственном номере

После настройки переведите приложение в `live`, разрешите только свой номер и запустите одно задание из интерфейса. Проверьте:

- Слышно представление ИИ и факты именно вашего продукта; переменные не озвучиваются фигурными скобками.
- Русский диалог, паузы и перебивание работают приемлемо.
- «Больше не звоните» даёт запись в списке запретов; повторная постановка этого номера отклоняется.
- «Мне интересно» сохраняет interested после явного согласия; тишина не считается интересом.
- Занято, отсутствие ответа, короткий сброс, предел длительности и кнопка остановки дают ожидаемые результаты.
- При остановке/ошибке во время подключения AI телефонная линия закрывается; поздно созданный AI client тоже закрывается.
- Журнал сервера и Voximplant содержат одно задание/один набор; финальный результат сохранён.
- Аудиозапись отключена и в Voximplant, и в настройках ElevenLabs.

Если персонализация не поступает до первого сообщения, остановите очередь и проверьте в Voximplant Cloud IDE порядок native initialization и опубликованные настройки агента. API-метод подтверждён документацией, но реальная версия коннектора и ваш агент должны пройти эту проверку. Не переходите к базе клиентов, пока собственный номер не прошёл все основные и негативные случаи.

## 6. Диагностика

| Симптом | Что проверить |
|---|---|
| Нет набора номера | Очередь не на паузе; допустимое время контакта; whitelist; claim HTTP 200; HTTPS; секреты |
| Claim неопределённый | Не повторять автоматически; проверить журнал провайдера и разрешить неопределённое задание вручную |
| Сразу ошибка до AI | Caller ID, баланс, направление; SIP-код в результате |
| Ответили, но AI молчит | API key, agent ID, публикация агента, лимиты ElevenLabs, metadata/error events |
| AI обещает действие, но оно не сохраняется | Client tool, точное имя, Wait for response, доступ сервера, ответ `stored:true` |
| Нет полного текста | События транскрипта включены у агента, обёртки событий, ограничения размера; тексты не являются записью аудио |
| Нет финального результата | Проверить сервер и провайдера; не переобзванивать автоматически |

Проверялись публичные API на 27.10.2026. Реальная платная линия в ходе разработки не запускалась.
