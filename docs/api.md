# API: подключить звонки к своему продукту

API доступен на том же HTTPS-домене, что панель. Внешнее приложение должно обращаться **с сервера**, с заголовком `Authorization: Bearer <ADMIN_TOKEN>`. Этот токен даёт административный доступ; не кладите его во фронтенд вашего публичного продукта. JSON, максимум тела 256 КБ. CORS для внешних браузеров не включён.

## Минимальный поток

1. `POST /api/contacts` — создать контакт с доказуемым согласием.
2. `POST /api/calls` — поставить задание. Повтор того же запроса с тем же `idempotency_key` возвращает прежнее задание.
3. `POST /api/queue` с `{"paused":false}` — разрешить обработку очереди. В live это запускает платные попытки в пределах окна и лимитов. Это общий переключатель всей очереди.
4. `GET /api/calls/{id}` — получить состояние и результат. Опрос раз в 5–10 секунд достаточен для небольшой интеграции.

Пример тела контакта (замените номер, основание и дату своими реальными данными):

```json
{
  "phone": "+7XXXXXXXXXX",
  "name": "Имя человека",
  "consent_source": "Идентификатор заявки с согласием на такой контакт",
  "consent_at": "2026-10-26T10:00:00+03:00",
  "timezone": "Europe/Moscow"
}
```

Placeholder номера специально невалиден. `timezone` можно опустить — применится `DEFAULT_TIMEZONE`. Телефон уникален; создание уже существующего возвращает 409. Поиск существующего контакта — по `GET /api/contacts`; редактирование согласия не реализовано.

Пример задания:

```json
{
  "contact_id": "id_из_ответа_контакта",
  "idempotency_key": "my-product:request-123:first-call",
  "not_before": "2026-10-28T09:30:00+03:00"
}
```

`not_before` необязателен. Держите ключ стабильным для одной бизнес-попытки. Не генерируйте новый ключ после таймаута: сначала повторите тот же запрос или прочитайте его результат. Иное содержимое с прежним ключом отклоняется. Новый ключ не позволяет обойти уже ожидающий/активный/неопределённый вызов того же номера.

## Маршруты

| Метод и путь | Назначение |
|---|---|
| `GET /health` | Публичная liveness-проверка, без состояния провайдеров |
| `GET /api/config` | Безопасные настройки, продукт, очередь и счётчики |
| `GET /api/contacts` | Контакты и отметка запрета звонков |
| `POST /api/contacts` | Создание контакта |
| `POST /api/contacts/import` | CSV UTF-8, `Content-Type: text/csv`, до 500 строк |
| `POST /api/calls` | Новое задание или прежний ответ по ключу |
| `GET /api/calls` | Последние 200 заданий, состояние очереди, счётчики |
| `GET /api/calls/{id}` | Одно задание, транскрипт, итог, метаданные |
| `POST /api/calls/{id}/stop` | Отмена ожидающего или запрос остановки активного |
| `POST /api/queue` | `{"paused":true}` останавливает новые и активные вызовы |
| `POST /api/calls/{id}/resolve` | Только `unknown`: `status` и проверочная `note` от 10 символов |
| `GET /api/suppressions` | Список «не звонить» |
| `POST /api/suppressions` | `{"phone":"…","reason":"…"}`: постоянный запрет |

У ответов списков есть поле `items`. У задания поле `status` принимает `queued`, `dispatching`, `starting`, `ringing`, `answered`, `completed`, `busy`, `no_answer`, `failed`, `cancelled`, `unknown`. Итог `outcome`: `interested`, `not_interested`, `callback`, `wrong_number`, `unknown`. Поле `mode` обязательно учитывайте: `mock` — синтетический результат.

Ошибки: 401 — нет доступа; 404 — запись отсутствует; 409 — конфликт/ограничение состояния; 413 — большой запрос; 422 — неверные поля; 429 — слишком много неверных попыток авторизации. Подробности в `detail`, для CSV — в `errors` со строками. CSV сначала полностью валидируется; затем дубликаты могут дать частичный импорт, проверяйте `imported` и `errors`.

Состояние `unknown` не считайте разрешением создать ещё один звонок. Ручной `resolve` выполняется после проверки истории и отсутствия активной линии у провайдера; он только фиксирует проверенный результат в приложении.

## Внутренний протокол VoxEngine

`/internal/calls/{id}/claim`, `/events`, `/control` предназначены для опубликованного сценария, не для интеграции продукта. Нужен `X-Internal-Secret`; события и контроль дополнительно требуют `X-Dispatch-Token`. Claim передаёт токен в JSON и может быть принят ровно один раз до истечения срока резервирования. События идемпотентны по `event_id`: повтор с иным содержимым — конфликт.

Эти маршруты обязаны быть доступны Voximplant по HTTPS. Не закрывайте их доступом только из локальной сети, если не настроили совместимую сеть. Их аутентификация отдельна от панели. Dispatch token не возвращается через административный API и не должен попадать в публичные логи.

Нет внешних webhooks с результатом, пагинации большой базы или многопользовательских ролей. Для этой небольшой версии интеграция получает результаты опросом; для высокой нагрузки сначала расширьте хранилище, авторизацию и модель доставки событий.
